# UX Audit Report - Expense Tracker AI

**Date:** December 24, 2025
**Scope:** Full application audit
**Auditor:** Claude Code

---

## Executive Summary

The Expense Tracker AI application demonstrates solid foundational UX with clean visual design, logical information architecture, and good mobile responsiveness. However, several opportunities exist to improve user efficiency, accessibility, and overall experience.

### Top 5 Key Findings

1. **Edit/Delete buttons hidden on hover** - Touch/keyboard users can't access critical actions
2. **No keyboard shortcuts** - Power users can't quickly add expenses or navigate
3. **Filter date inputs lack labels** - Accessibility issue, users don't know which is "from" vs "to"
4. **No undo for delete** - Destructive action requires modal but no recovery option
5. **Mobile menu doesn't close on route change** - Can cause confusion on navigation

---

## Detailed Findings

### Usability

#### Finding: Action buttons only visible on hover
**Problem:** Edit and delete buttons in ExpenseItem are hidden until mouse hover (`opacity-0 group-hover:opacity-100`), making them inaccessible to touch users and non-obvious to new users.
**Location:** `src/components/expenses/ExpenseItem.tsx:56`
**Impact:** High - Core functionality hidden from mobile/touch users
**Recommendation:** Always show action buttons, or use a more accessible reveal pattern (swipe on mobile, focus-within for keyboard)
**Implementation:**
```tsx
// Option A: Always visible (simpler)
<div className="flex items-center gap-1">

// Option B: Focus-within for accessibility
<div className="flex items-center gap-1 opacity-0 group-hover:opacity-100 group-focus-within:opacity-100 sm:opacity-100">
```

---

#### Finding: No quick-add functionality
**Problem:** Users must navigate to a separate page to add an expense, adding friction to the most common action.
**Location:** Application-wide
**Impact:** Medium - Increases time to complete primary task
**Recommendation:** Add a floating action button (FAB) or quick-add modal accessible from any page
**Implementation:**
- Add a fixed-position FAB in the bottom-right corner
- Opens a modal with the expense form
- Persists across all pages via layout.tsx

---

#### Finding: No keyboard shortcuts
**Problem:** Frequent users cannot use keyboard shortcuts to speed up common actions (add expense, navigate, search).
**Location:** Application-wide
**Impact:** Medium - Power users frustrated by repetitive clicking
**Recommendation:** Implement keyboard shortcuts for common actions
**Implementation:**
- `Cmd/Ctrl + N` - New expense
- `Cmd/Ctrl + K` - Focus search
- `/` - Focus search (when not in input)
- `Escape` - Close modals (already implemented)

---

#### Finding: Form doesn't remember last category
**Problem:** Category defaults to "food" every time, even if user typically logs different categories.
**Location:** `src/components/expenses/ExpenseForm.tsx:36`
**Impact:** Low - Minor convenience issue
**Recommendation:** Remember last used category in localStorage
**Implementation:** Store last category in localStorage, use as default for new expenses

### Feedback & Affordances

#### Finding: No feedback after CSV export
**Problem:** Clicking "Export CSV" triggers a download but provides no visual confirmation. Users may click multiple times thinking it didn't work.
**Location:** `src/app/page.tsx:19-23`, `src/app/expenses/page.tsx:29-33`
**Impact:** Medium - Users uncertain if action succeeded
**Recommendation:** Show a toast notification confirming the export
**Implementation:**
- Add a toast/snackbar component
- Show "Expenses exported successfully" message
- Auto-dismiss after 3 seconds

---

#### Finding: No loading indicator on form submission
**Problem:** While there is an `isLoading` prop, the artificial 300ms delay in add page submission doesn't show immediate feedback.
**Location:** `src/app/add/page.tsx:20-29`
**Impact:** Low - Button shows loading state correctly, but could be faster
**Recommendation:** Remove artificial delay, trust the loading state
**Implementation:** Remove `setTimeout` wrapper, just call `addExpense` directly

---

#### Finding: Delete action lacks undo option
**Problem:** Once an expense is deleted, there's no way to recover it. While there's a confirmation modal, accidental deletions still happen.
**Location:** `src/components/expenses/ExpenseItem.tsx:24-27`
**Impact:** Medium - Data loss risk
**Recommendation:** Implement soft delete with undo toast
**Implementation:**
- Don't immediately remove from state
- Show "Expense deleted" toast with "Undo" button
- Auto-remove after 5 seconds if not undone
- On undo, restore the expense

### Information Architecture

#### Finding: Insights page is too minimal
**Problem:** The Insights page contains only one component with limited information. Users expect more value from a dedicated insights page.
**Location:** `src/app/insights/page.tsx`
**Impact:** Medium - Page feels incomplete
**Recommendation:** Add more insights or consolidate into Dashboard
**Implementation:**
- Add week-over-week comparison
- Add spending goals/budgets
- Add insights like "You spent 20% more on food this month"
- Or: Remove as separate page, integrate MonthlyInsights into Dashboard

#### Finding: No way to sort expenses
**Problem:** Expense list only shows expenses in one order. Users may want to sort by amount, date, or category.
**Location:** `src/app/expenses/page.tsx`
**Impact:** Low - Filtering exists but sorting would help
**Recommendation:** Add sort dropdown (Date newest/oldest, Amount high/low)
**Implementation:** Add sort state, sort options dropdown, apply before mapping

### Accessibility

#### Finding: Filter date inputs lack visible labels
**Problem:** Date inputs for "From" and "To" dates have placeholder text but no accessible labels. Screen readers won't announce purpose.
**Location:** `src/components/expenses/ExpenseFilters.tsx:64-76`
**Impact:** High - Accessibility violation
**Recommendation:** Add proper labels to date inputs
**Implementation:**
```tsx
<Input
  label="From Date"
  type="date"
  value={filters.dateFrom}
  ...
/>
<Input
  label="To Date"
  type="date"
  value={filters.dateTo}
  ...
/>
```

---

#### Finding: Charts not accessible to screen readers
**Problem:** Recharts pie/bar charts provide no text alternative for screen reader users.
**Location:** `src/components/dashboard/CategoryChart.tsx`, `MonthlyTrendChart.tsx`
**Impact:** Medium - Chart data invisible to some users
**Recommendation:** Add aria-label with summary or visually hidden summary text
**Implementation:**
- Wrap charts in a div with `aria-label="Category breakdown: Food 45%, Bills 30%..."`
- Or add a visually-hidden `<dl>` with the same data

---

#### Finding: Focus trap not implemented in modals
**Problem:** While modals trap scroll, focus can escape to content behind the modal when tabbing.
**Location:** `src/components/ui/Modal.tsx`
**Impact:** Medium - Accessibility issue for keyboard users
**Recommendation:** Implement focus trap within modal
**Implementation:** Use a focus-trap library or implement manual focus management with first/last focusable element cycling

---

#### Finding: Color contrast on disabled buttons
**Problem:** Disabled buttons use `opacity-50` which may not meet WCAG contrast requirements.
**Location:** `src/components/ui/Button.tsx:23`
**Impact:** Low - May affect some users
**Recommendation:** Use explicit disabled colors rather than opacity
**Implementation:** Replace `disabled:opacity-50` with `disabled:bg-gray-300 disabled:text-gray-500`

---

### Mobile Experience

#### Finding: Mobile menu doesn't auto-close on navigation
**Problem:** When clicking a nav link on mobile, the menu stays open until manually closed.
**Location:** `src/components/layout/Header.tsx:106-118`
**Impact:** Medium - Confusing UX on mobile
**Recommendation:** Menu already closes on click - verified this is implemented correctly at line 115
**Note:** This was a false positive upon closer inspection. The `onClick` handler calls `setIsMobileMenuOpen(false)`.

---

#### Finding: Touch targets on expense item actions may be too small
**Problem:** Edit/delete buttons are `size="sm"` which may result in touch targets under 44x44px minimum.
**Location:** `src/components/expenses/ExpenseItem.tsx:57-96`
**Impact:** Medium - Difficult to tap on mobile
**Recommendation:** Increase button size or add padding to hit area
**Implementation:** Use `size="md"` or add `min-w-[44px] min-h-[44px]` wrapper

---

#### Finding: Horizontal scroll possible on mobile
**Problem:** Some content may cause horizontal overflow on narrow screens, particularly the summary bar and filter grid.
**Location:** `src/app/expenses/page.tsx:122-130`
**Impact:** Low - May not always occur
**Recommendation:** Add `overflow-x-hidden` to main container or test thoroughly at 320px width

---

### Performance Perception

#### Finding: No skeleton for individual components
**Problem:** While page-level loading skeletons exist, individual cards don't show loading states if data updates.
**Location:** Dashboard, Expenses pages
**Impact:** Low - Initial load is handled well
**Recommendation:** Consider adding component-level loading for future async features

---

#### Finding: Charts render after paint causes layout shift
**Problem:** Recharts ResponsiveContainer measures after mount, causing a brief layout shift.
**Location:** All chart components
**Impact:** Low - Minor visual jank
**Recommendation:** Set explicit heights on chart containers (already done with `h-64`)
**Note:** This is already handled correctly.

## Summary

The Expense Tracker AI application has a solid foundation with good visual design and logical structure. The most critical improvements are accessibility-related (filter labels, button visibility, chart descriptions) and should be prioritized. The app would benefit from modern patterns like undo functionality and keyboard shortcuts to improve power user efficiency.

**Recommended Next Steps:**
1. Address the 4 "Quick Wins" immediately
2. Plan implementation of undo/toast system
3. Conduct accessibility audit with automated tools (axe, Lighthouse)
4. User testing with keyboard-only navigation
